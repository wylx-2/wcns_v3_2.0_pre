# WCNS v2.0.0 详细开发计划

状态：**2026-09-12 计划候选 v1，等待项目负责人人工冻结；尚未开始 v2.0.0 生产代码开发。**

基线版本：WCNS v1.1.0；计划版本：WCNS v2.0.0。数学与数值算法以仓库根目录
[`算法补充.md`](../算法补充.md) 第 12 节为计划权威规格；开发流程、Git 管理和公共卡口同时受
[`development-roadmap.md`](development-roadmap.md) 约束。Case06 当前输入身份和待确认条件见
[`v2.0.0/case06-intake.md`](v2.0.0/case06-intake.md)。

本计划延续 v1.0/v1.1 的“先规格、后代码；每阶段自动卡口、人工判断、不可移动候选标签”流程。
项目仍采用本机独立开发，**不恢复 GitHub Actions 或其他外部 CI**；全部质量证据由固定本机的
串行/MPI Release 构建、CTest、数值验证脚本和人工图表审查形成。

## 1. 版本目标

v2.0.0 定位为“可验证的定常低速 RANS 外流与三维机翼能力”版本。完成时必须做到：

1. 在现有结构多块、WCNS、CGNS 和 MPI 框架中支持统一的 RANS 附加输运场、壁距、湍流黏度、
   边界条件、输出和可改变 rank 数的重启；`laminar` 路径保持 v1.1.0 行为。
2. 提供至少两个生产支持级的常用湍流模型：`sa_neg` 和明确变体的 `k_omega_sst`；提供标准
   `k_epsilon` 及显式壁面处理接口，证据不足时只能标为实验功能，不能冒充已验证模型。
3. 建立瞬时和时间累计的壁面/边界层统计，包括 `Cp/Cf/y+`、摩擦速度、热流、涡黏度比、
   湍流变量、均值/RMS/协方差、整体与截面载荷，并保证 MPI/restart 一致。
4. 对 Roe 路径实现完整的 Weiss--Smith 型低 Mach 定常伪时间预处理，覆盖特征速度、通量耗散、
   局部时间步、更新矩阵、远场边界和失败回退；在高 Mach 极限严格恢复未预处理行为。
5. 增加适合高 Reynolds 数外流收敛的本地时间步和 point-implicit/LU-SGS 级加速、平均流/模型
   残差与载荷窗口联合停止、网格质量/壁面分辨率报告。
6. 完成用户提供的 Case06 NACA0012 二维算例计算、数值收敛和可追溯比对。
7. 在用户后续提供目标条件后，完成最终三维翼型/机翼算例，包括 MPI、截面载荷、表面统计、
   收敛与网格/模型不确定性说明。
8. 形成内部可复现的 v2.0.0 源码、配置、算法、验收和版本说明；对外发布和许可证继续暂缓，
   不作为本版本卡口。

## 2. 当前基线与缺口

### 2.1 可复用能力

- v1.1.0 已有五分量层流 Navier--Stokes、常黏度/Sutherland、Prandtl、SSPRK3、
  Rusanov/HLLC/Roe、两套 WCNS profile、物理容许性/逐面降阶和整步重试。
- 已有结构多块 CGNS、运行时切分、非阻塞 MPI halo、共享面权威通量、边界真实迹、壁压/牵引/
  热流、`Cp/Cf`、力/力矩和同/异 rank 重启。
- 已有 field/statistic registry、残差历史、平面统计和简单槽道壁统计，可作为扩展接口，但当前
  槽道量只是瞬时空间平均，不能作为湍流时间统计。
- v1.1.0 正式标签为 `v1.1.0`，当前主干基准提交在计划建立时为 `00bb903`；计划冻结时必须
  重新记录实际提交、编译器、MPI 和测试清单。2026-09-12 的计划前只读回归为本机串行
  Release 60/60、Intel MPI Release 108/108 通过，可作为阶段 V 重建基线的参考而非替代证据。

### 2.2 必须解决的结构缺口

1. `StructuredBlock` 当前只有固定五分量平均流，缺少模型可注册附加场、标量 halo/重构/扩散、
   模型源项和检查点 schema。
2. 黏性通量只使用分子黏度/导热，尚无 Reynolds 应力、湍流热通量和湍动能各向同性项。
3. 没有全局最近壁距；索引层数或局部法向距离不足以支持曲面、多块和三维机翼。
4. 当前 Riemann 接口只接收左右平均流状态和法向，低 Mach 所需参考速度、局部尺度、伪时间
   特征系统与远场边界没有统一上下文。
5. 当前定常停止以残差为主，没有模型残差、力/矩窗口、伪时间局部步和刚性源隐式处理。
6. 当前统计不保存累计权重和二阶矩，不能在重启后继续可靠的均值/RMS/Reynolds 应力。
7. Case06 只有网格，缺少经确认的工况、壁面热条件、湍流远场量和目标数据；单网格也不能单独
   证明网格无关。
8. 最终三维目标算例尚未提供，相关阶段必须允许等待输入而不伪造验收条件。

## 3. 范围边界

### 3.1 必做范围

- Favre 平均可压缩 RANS 基础设施、Boussinesq 线性涡黏性闭合和可配置 $Pr_t$；
- 维数无关的物理壁面距离，支持结构多块、运行时切分和 MPI；
- fully turbulent `sa_neg`；
- 明确且不混用变体的 `k_omega_sst`；
- 标准 `k_epsilon` 和显式 `resolved|wall_function` 接口；若模型验证不足，最终必须显式标为
  experimental，但接口、公式测试和失败边界仍须完成；
- turbulence-aware 的边界/初场/远场、标量对流扩散和刚性源处理；
- 定常 Roe/Weiss--Smith 预处理、本地伪时间步、point-implicit 或 LU-SGS；
- 壁面/时间/截面统计，重启连续性和串并行一致性；
- Case06 和一个用户后续提供的三维翼型/机翼目标算例；
- 本机严格自动验收、阶段人工放行、文档与 Git 证据闭环。

### 3.2 条件增强项

只有核心任务按期过卡且阶段设计另行冻结时才允许进入，不得阻塞或污染核心路径：

- 低 Mach 多重网格、网格序列或更强 Krylov 线性求解；
- 点涡修正远场、自动攻角扫描和 restart continuation；
- `k_epsilon` 的 realizable/RNG 变体；
- 物理时间准确的低 Mach 双时间步 URANS；
- 更复杂的曲率/旋转修正或 QCR 非线性应力修正；
- HDF5/并行 CGNS、自动网格生成或自动网格自适应。

### 3.3 明确非目标

- LES、DES/DDES、RANS/LES 混合、DNS 专用能力和 Reynolds 应力模型；
- $\gamma-Re_\theta$ 等转捩模型。若 Case06/三维目标要求自然转捩，先修订版本范围；
- 多组分、燃烧、化学反应、真实气体、辐射、共轭换热；
- 非结构/混合/重叠网格、非共形接口、运动/变形网格和 AMR；
- 伴随、气动优化、流固耦合、旋翼运动和完整飞行器自动化；
- 为本地项目重新建立外部 CI、对外发布或替项目负责人作许可证决定。

## 4. v2.0.0 不可破坏契约

1. `turbulence.model=none` 时不分配模型场、不改变平均流残差、时间步、输出顺序或 v1.1.0
   默认配置语义；受影响基线必须逐位或按冻结的舍入容差一致。
2. 模型场与平均流共享块拓扑、owner、halo 版本和接受事务；任何一项非法时整个候选子步/伪
   时间步拒绝，不能提交“平均流新、湍流量旧”的混合状态。
3. 每个湍流模型只有一个权威变体标识、常数表和参考来源；常数、limiter、远场值、壁面处理、
   $Pr_t$ 和轨迹相关 floor 全部进入摘要、manifest 和 restart signature。
4. SA-neg 允许模型定义内的有限负工作变量；`k/omega/epsilon` 必须严格正。容许域策略是检测、
   一致降阶和拒绝，不是无日志裁剪。
5. 全局壁距只由命名物理 wall patch 产生，跨 rank 数/分区保持一致；人工切分面和连接面不算壁。
6. 平均流中的分子/湍流应力和热流只在一个权威黏性通量路径组合，边界统计复用同一物理定义；
   后处理不得再用另一套符号、法向或导数近似。
7. 低 Mach 预处理只改变伪时间和数值耗散，不改变目标定常方程；`beta=1` 必须严格恢复普通 Roe
   特征和谱半径。`preconditioner=none` 时保留既有 Riemann 路径。
8. 预处理选择、Riemann、CFL、远场和稳健性回退是一个受验证组合；不支持的组合在初始化前
   一致拒绝，不能静默退化。
9. 时间统计只累计已接受的完整步，保存权重、均值和二阶中心矩；重试、重复事件和输出重读
   不得双计。
10. Case06 和三维目标的“程序可运行”“离散已收敛”“与参考数据一致”是三个不同结论，报告
    必须分别给证据和局限。
11. 任何性能优化不得与模型公式变更混合提交；每项优化必须有前后数值证据和可回退提交。
12. 用户输入文件默认只读；未获明确批准不得移动、改写、格式化、暂存或纳入发行包。

## 6. 每阶段统一执行步骤与卡口

### 6.1 统一步骤

1. **登记基线**：提交号、分支、工作树、用户文件、工具链、硬件、串行/MPI 测试数和性能摘要。
2. **编写设计**：新增 `docs/v2.0.0/stage-<id>-design.md`，列明公式引用、接口、数据所有权、
   边界、失败语义、配置/restart 影响、测试矩阵、阈值和非目标。
3. **人工冻结设计**：涉及数学/范围的更改先更新《算法补充》和本计划。设计未批准不得修改
   该阶段生产 C++。
4. **小提交实现**：公式/接口、实现、测试、文档和性能优化分开提交；每个提交运行最小受影响集。
5. **阶段前验**：使用临时干净构建，运行公式、单元、数值、失败、串行/MPI 和重启专项。
6. **正式自动验收**：从候选提交重新构建，保存命令、环境、原始日志、阈值、结果和哈希到
   `docs/v2.0.0/stage-<id>-acceptance.md`。
7. **候选与人工判断**：自动全过后创建不可移动的 `v2.0.0-<id>-candidate.N`，停下供人工检查。
8. **批准后合并**：记录批准提交/日期，可加 `approved.N` 标签，以 `--no-ff` 合入
   `release/v2.0.0`；要求修改则保留旧候选并递增编号重验。

### 6.2 公共自动卡口

| 卡口 | 必须满足 | 失败处理 |
|---|---|---|
| G0 范围 | 设计、公式、变体、阈值、非目标已冻结 | 不开始生产实现 |
| G1 接口 | 所有权、维数、单位、合法域、边界、MPI/restart 唯一 | 返回设计修订 |
| G2 静态 | `git diff --check`、格式/警告、配置和文档检查通过 | 不做数值验收 |
| G3 构建 | 本机串行/MPI Release 从干净目录构建、安装通过 | 正式验收失败 |
| G4 单元/公式 | 新公式、常数、极限、索引、非法输入和故障注入有测试 | 正式验收失败 |
| G5 全回归 | v1.1 及当前全部串行/MPI CTest 通过 | 禁止解释性放行 |
| G6 数值 | MMS/解析/基准的阶、守恒、渐近和载荷阈值通过 | 不得事后放宽 |
| G7 并行/重启 | 多块、1/2/4 rank、共享面、异 rank 重启和一致失败通过 | 正式验收失败 |
| G8 证据 | 报告、配置、脚本、日志、图表、哈希、提交与工作树可审计 | 不创建候选 |
| G9 人工 | 项目负责人明确批准候选 | 不合并、不进入下一阶段 |

本机独立开发不等于减少矩阵：正式卡口至少保留一个串行 Release 和一个 Intel MPI Release
构建；必要的 Debug/sanitizer 可在本机可用工具链中增加，但不以外部 runner 为真值。

## 7. 阶段 V：规格、输入与基线冻结

### 7.1 任务

1. V0：人工审查本计划、《算法补充》第 12 节和 Case06 登记，冻结核心/条件/非目标。
2. V1：选择 SA-neg、SST 的精确变体、总能是否含 $k$、$Pr_t$、生产 limiter、模型 floor 和
   wall treatment 语义；建立常数/来源/实现名三向表。
3. V2：记录 `v1.1.0` 标签、主干提交、工具链、CPU/MPI、现有测试和固定机器性能基线。
4. V3：用 WCNS reader、`cgnslist`、`cgnscheck` 对 Case06 做只读 intake，确认连接互逆、度量、
   边界覆盖和自由流保持；决定网格的 Git/本机资产策略。
5. V4：定义目标三维算例 intake 模板，明确用户以后必须提供的几何、工况、参考量和验证数据。
6. V5：冻结配置草案：`turbulence.*`、`preconditioner.*`、`pseudotime.*`、`statistics.time.*`、
   `output.sections.*`；先写合法/非法样例，不接生产 parser。
7. V6：冻结 V--AE 的测试映射、验收报告 schema、数值证据保存体积和本地运行预算。

### 7.2 自动卡口

- 当前串行/MPI Release 全测试通过，数目、耗时和失败注入清单入库；
- `turbulence=none, preconditioner=none` 基线保存字段、残差、载荷和 checkpoint 哈希；
- Case06 文件哈希与 intake 一致，读取/覆盖/连接/自由流 smoke 不改写原文件；
- 所有引用的模型变体、常数和低 Mach 公式在《算法补充》中有唯一来源；
- 配置草案拒绝未知模型、模型无关参数、非法组合和非有限值；
- 工作树只允许 intake 已登记的用户文件，正式证据不包含大场文件。

### 7.3 人工判断

人工重点选择：SA/SST 精确变体；`k_epsilon` 是正式还是先按实验目标开发；Case06 网格资产
策略；首个低 Mach 支持范围是否仅定常；本地可接受的长算预算。未批准时保持计划分支，不创建
任何 v2 生产阶段分支。

## 8. 阶段 W：通用 RANS 基础设施

### 8.1 任务

1. W0：设计 `TurbulenceModelConfig`、`ITurbulenceModel`、模型 registry、变量 descriptor 和
   `TurbulenceFieldSet`；模型负责变量/源/扩散/边界/诊断，driver 负责生命周期和事务。
2. W1：把任意少量附加 cell scalar 接入块存储、ghost、连接变换、非阻塞 MPI halo、重构、
   对流面通量、梯度和扩散；标量不得进入平均流特征向量。
3. W2：建立模型场的初始化、物理边界、共享面权威通量、容许性、逐面降阶和整步拒绝。
4. W3：实现第 12.3 节壁距，含二维 segment、三维 triangle、BVH、确定性 MPI 最小归约和输出。
5. W4：将 $\mu_t$、Reynolds 应力和湍流热通量接入唯一黏性通量及边界量路径；`mu_t=0`
   必须恢复层流。
6. W5：实现刚性源局部隐式/解析更新接口，给线性生成/耗散标量制造问题验证时间一致性。
7. W6：扩展配置、manifest、field output、checkpoint 和 restart signature；旧检查点只允许在
   `model=none` 时按明确兼容映射读取。

### 8.2 自动卡口

- `model=none` 与 V 基线一致；零涡黏度 dummy 模型与层流路径在冻结容差内一致；
- 一、二、三个附加标量均通过周期对流、扩散和带源制造解的预期空间/时间阶；
- scalar halo 在原生多块、运行时 i/j/k 切分、轴变换和 1/2/4 rank 下逐项一致；

1. v2 新增模型场和伪时间语义，计划将配置 schema 升为 2；parser 可读取 schema 1 并严格迁移
   为 `model=none, preconditioner=none`，但 schema 2 的模型配置不得回写成含糊 schema 1。
2. 建议命名空间：`turbulence.model/transport/farfield/wall_treatment/floors`、
   `preconditioner.type/mach_cutoff/viscous_cutoff`、`pseudotime.local/solver/cfl`、
   `statistics.time/start/end/every`、`output.sections`。最终键在对应阶段设计冻结。
3. parser 拒绝未知键、重复键、非有限量、模型无关参数和不支持组合；摘要打印最终生效值、来源
   和模型变体，不只回显输入。
4. v1.1 checkpoint 只在 schema 迁移后仍为 laminar/无预处理且数值签名一致时恢复。RANS
   checkpoint 必须带变量 descriptor、模型/常数、壁距身份、统计累加器和伪时间签名。
5. 每个键同步更新模板、用户手册、开发指南、算法、合法/非法测试和 manifest；不得长期形成
   代码已支持而文档未定义的隐藏配置。

## 19. v2.0.0 完成定义

只有同时满足以下条件才能称为完成：

1. V--AE 全部阶段有设计、自动报告、不可移动候选和人工批准记录；
2. v1.1 laminar/Euler 兼容路径全回归，所有本机串行/MPI Release 卡口通过；
3. SA-neg 与 SST 达生产支持级，k-epsilon 的实际支持级别与证据/文档一致；
4. 壁距、RANS 应力/热流、模型输运、边界、输出和同/异 rank 重启一致；
5. 低 Mach 预处理覆盖矩阵、通量、谱半径、伪时间、远场和回退，证明渐近正确与真实加速；
6. 壁面/时间/截面统计定义、抽样、checkpoint 和 MPI 加和可审计；
7. Case06 和用户目标三维翼型均获人工接受，且分别说明收敛、离散、模型和参考不确定性；
8. 配置、算法、用户/开发手册、限制、版本说明、安装树和内部源码包与实现一致；
9. `v2.0.0-rc.N` 在合并主干前通过最后人工核验，之后才创建正式标签并同步远程；
10. 外部 CI、对外发布和许可证仍按项目负责人当前决定暂缓，不被文档暗示为已完成。
