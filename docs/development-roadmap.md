# WCNS 后续开发流程与阶段检查卡口

状态：阶段 H--O 已完成并形成 v1.0.0；v1.1.0 阶段 P--U 的自动卡口和最终人工核验均已
通过。发布前无功能清理及本机串行/MPI 全量回归已完成，已合入 `release/v1.1.0` 和
`main` 并创建正式版本。首次远程同步后已按本机独立开发决定移除外部 CI；对外发布和许可证
决定继续暂缓。

本文固定 v1.0.0 阶段 H--O 和 v1.1.0 阶段 P--U 的开发顺序、交付物、自动验收和人工放行规则。
数学与算法定义以仓库根目录的 `算法补充.md` 为准；阶段 M--O 的详细接口、停止/输出契约、
结构分区和算例矩阵以 [`release-development-plan.md`](release-development-plan.md) 为准；阶段
P--U 的范围、任务和量化验收以 [`v1.1.0-development-plan.md`](v1.1.0-development-plan.md)
为准。本文规定如何实施和验收，任何临时计划、聊天结论或测试通过都不能绕过当前有效卡口。

## 1. 不可变原则

1. 阶段 H--O 保留 v1.0.0 的历史顺序和验收记录。v1.0.0 的 M、N 曾按批准的流程例外在自动
   验收后按 M、N、O 连续开发，O 执行集中人工验收；该历史例外不延续到 v1.1.0。
2. v1.1.0 严格按 P、Q、R、S、T、U 顺序开发。项目负责人于 2026-09-11 明确授权 P→Q 和
   R→S→T 连续推进：获连续授权的阶段自动验收通过后可合入版本集成分支并直接进入下一阶段。
   该例外不取消任何设计、自动卡口、报告或 Git 证据，也不自动延伸到 T→U；T 候选随后取得
   单独人工批准，才进入 U。
3. 开始一个阶段前，先把该阶段拆成可独立验收的小任务；每个小任务完成后必须提交 Git，并同步到 GitHub 的当前阶段分支。
4. 阶段候选、阶段人工批准和正式版本是三个不同状态。阶段候选不能进入下一阶段；只有最终
   U 候选人工批准后才允许合并 `main` 和创建正式 `v1.1.0` 标签。
5. 正式验收无论成功或失败都必须进行一次 Git 管理。开发过程中普通的编译失败不算正式验收；正式验收开始后必须在验收报告中记录命令、结果和结论。
6. 不使用强制推送，不移动既有标签，不改写已经同步的提交历史。候选版本修订时创建新的候选标签。
7. 现有用户修改和无关工作必须保留。禁止用 `git reset --hard`、覆盖式 checkout 或清理整个工作区来处理冲突。
8. 算法定义发生变化时，先修订 `算法补充.md`、本路线图和当前版本计划，完成规格核验与 Git 管理，再修改实现。
9. 所有物理量、索引范围、拓扑位置、消息种类和算法 profile 必须只有一个权威定义；不得为通过测试而建立未记录的旁路或静默低阶回退。

## 3. Git 与 GitHub 工作流

本流程从阶段 H 开始，不追溯改写阶段 A--G 的历史。

### 3.1 阶段开始

阶段 H--L 按各自历史批准记录执行。阶段 M--O 使用连续发布开发线：

1. 从当前阶段 L 候选的干净提交建立 `stage/release`；不要求先把 K/L 追认为人工通过或合并 `main`。
2. 每阶段开始前新建或更新 `docs/stage-<x>-design.md`，列出小任务、接口、测试和非目标。
3. 推送发布开发分支。M、N 只有在上一阶段正式自动验收通过后才可开始，但不再等待人工回复。
4. 阶段 O 发布候选通过集中人工验收后，才把发布开发线非快进合并到 `main`。

### 3.2 小任务提交

每个小任务执行以下闭环：

```text
检查工作树和相关代码
-> 实现一个边界明确的小目标
-> 运行该目标的最小测试和受影响回归
-> git diff --check
-> 提交一个主题明确的 commit
-> 推送当前阶段分支
-> 开始下一个小任务
```

提交不得混入无关格式化、生成物或其他阶段功能。若小任务尚未满足其局部验收，不把它标记为“完成”；需要保存诊断工作时，提交信息必须明确包含 `wip` 或 `diagnostic`，且不能作为候选标签目标。

### 3.3 正式自动验收

只有全部小任务完成后才能声明正式验收。每次正式验收必须：

1. 从干净构建或确认过的构建配置执行本文规定的公共测试和当前阶段专项测试。
2. 在 `docs/stage-<x>-acceptance.md` 中记录提交号、编译器、MPI 配置、命令、通过数量、容差、失败项和已知限制。
3. 提交验收报告并推送阶段分支。
4. 自动验收成功时创建不可移动的 `stage-<x>-candidate-v<n>` 标签并推送；首次候选使用 `v1`。
5. 自动验收失败时不创建候选标签、不合并 `main`、不进入下一阶段。失败报告仍需提交；修复后在同一分支进行下一次正式验收。

GitHub 暂时不可访问时，可以先保留本地提交和标签，但必须明确报告“远程未同步”，并在网络恢复后补推。阶段 O 提交最终人工验收前必须完成远程同步；短暂的远程故障不阻塞 M、N 的本地后续开发。

### 3.4 人工放行

- K、L 尚未进行的人工检查并入阶段 O 的发布级算例验收，不再单独阻塞 M 或 N；这项流程变更不追认其旧候选为人工通过。
- M、N：自动卡口通过后记录里程碑并直接继续，不合并 `main`。
- O 项目负责人批准：将发布候选以非快进方式合并到 `main`，创建正式版本标签并推送。
- O 项目负责人要求修改：保留原发布候选标签，在发布开发线上修复，重新执行受影响测试及完整发布级验收，创建递增候选标签。
- 项目负责人拒绝阶段方案：停止对应实现，先修订设计/算法文档；未获新指令不得自行换方案。

### 3.5 v1.1.0 分支与逐阶段人工放行

v1.1.0 使用 `release/v1.1.0` 作为版本集成分支，P--U 分别使用
`stage/v1.1.0-<p-u>`。通常阶段分支从上一阶段已人工批准并合入的版本集成提交建立，自动验收
成功后创建 `v1.1.0-<stage>-candidate.N`，人工批准后以 `--no-ff` 合入。唯一当前例外是 P：
其候选自动过卡后可直接非快进合入并建立 Q 分支。Q 候选必须等待人工批准，随后才允许进入 R。
最终 U 使用 `v1.1.0-rc.N`，人工批准后才合并 `main` 并创建 `v1.1.0`。

阶段开始前必须登记工作树中已有用户文件并优先使用独立 worktree。候选标签、人工批准记录、
阶段验收报告和远程提交必须指向可相互核对的提交；任何失败候选或旧报告均不得通过改写历史
删除。详细命名、提交粒度和失败处理见 v1.1.0 计划第 12 节。

## 4. 所有阶段共用的检查卡口

| 卡口 | 必须满足的条件 | 失败处理 |
|---|---|---|
| G0 范围冻结 | 本阶段设计文档、小任务、非目标和验收量化标准已明确 | 不开始实现 |
| G1 接口与合法域 | 新接口有唯一职责；真实/ghost、cell/face/vertex、owner/receiver 范围可检查 | 修改设计和单元测试 |
| G2 构建与静态检查 | 串行和 MPI Release 构建通过；`git diff --check` 通过；无意外未跟踪文件 | 不开始数值验收 |
| G3 单元与公式 | `python tools/verify_algorithm_spec.py` 通过；新增公式、变换、索引和异常路径均有测试 | 修复后重跑全部 G3 |
| G4 串行回归 | `ctest --test-dir build -C Release --output-on-failure` 全通过 | 正式验收失败 |
| G5 MPI 回归 | `ctest --test-dir build-mpi -C Release --output-on-failure` 全通过；当前阶段指定的多 rank 测试通过 | 正式验收失败 |
| G6 数值验收 | 当前阶段的解析解、制造解、收敛阶、守恒和等价性指标达到明确容差 | 不得用放宽容差静默通过 |
| G7 文档与可追溯性 | 设计、配置、日志字段、验收报告、提交和远程候选标签完整 | 不提交人工验收 |
| G8 发布人工放行/阶段人工放行 | v1.0.0 仅 O 要求发布人工放行；v1.1.0 除获书面连续授权的 P、R、S 外均要求明确批准候选 | P/R/S 按对应授权连续推进；T 未批准不得进入 U；U 未批准不得创建正式版本 |

所有测试只访问真实合法域的要求必须通过 NaN/哨兵或调试断言验证。新增并行消息必须验证消息种类、阶段号、版本、长度和 donor/receiver 映射，不能仅验证“程序未崩溃”。

## 5. 阶段 H：核心热力学、合法域与源项框架

状态：`stage-h-candidate-v1` 已于 2026-08-31 获项目负责人批准，允许按流程进入阶段 I。

### 5.1 目标与小任务

1. H1：实现 `ReferenceScales`。只接受五个正参考量，拒绝输入 `Re`/`Ma`，派生并记录 $Re$、$Ma$ 和参考动压。
2. H2：实现量热完全理想气体 `GasModel`，严格执行 `molar_mass`/`specific_gas_constant` 二选一，并统一完成 primitive/conservative、$p,T,a,h$ 换算。
3. H3：实现 `NumericalFloors`、`ReconstructionScaling` 的基础容器和集中校验，不把阈值散落到算法模块。
4. H4：实现强类型 cell/vertex/face/range、字段拓扑位置和调试合法域检查；物理边界边/角及非状态 ghost 保持非法。
5. H5：实现 `SourceTermConfig/Registry` 空框架和关闭路径；不实现实际源项推进。
6. H6：把新基础设施接入现有程序，但源项默认关闭，现有有限体积 Euler 结果不得变化。

### 5.2 阶段 H 卡口

- 含 `Re` 或 `Ma` 的输入确定性失败；只给五个参考量时，各 rank 派生值一致并出现在 log/检查点。
- primitive/conservative 往返、二维 $w=0$、正温度/压力和非法状态路径均有单元测试。
- `molar_mass` 和 `specific_gas_constant` 同时给出或同时缺失时失败。
- 对非法 topology/range/ghost 访问有调试断言测试；NaN 边角和非状态 ghost 不被读取。
- `enable_source_terms=false` 不创建或调用源项模型，现有代表算例与阶段 E 基线逐位一致。
- 公共 G0--G8 全部满足。阶段 H 不允许实现新度量、WCNS 高阶通量或粘性通量。

## 6. 阶段 I：两套几何 profile

状态：`stage-i-candidate-v2` 已于 2026-09-01 通过自动及人工验收，允许进入阶段 J。

### 6.1 目标与小任务

1. I1：实现只能成套创建部件的 `AlgorithmProfile/ProfileFactory`，禁止跨 profile 拼装。
2. I2：实现 `phenglei_wcns` 加密交错工作区、`GridDelta`、对称守恒面矢量和 Jacobian。
3. I3：实现 `scmm6_wcns` 的 $I_6^{v\to c}$、$I_6/D_6$ SCMM、面矢量和 Jacobian。
4. I4：实现 `GeometryHaloPlan`、分阶段 `GeometryOperand`、共享面所有者、轴置换/反向及周期 $Q/\boldsymbol d$。
5. I5：实现 `reference_volume/reference_area` 诊断和 `GlobalConservationWeights`。
6. I6：冻结只包含真实单元 $J$、真实面 $\boldsymbol S$ 和真实 `CellCoordinates` 的 `MetricField`。

### 6.2 阶段 I 卡口

- 恒等映射逐点得到 $J=1$ 和解析笛卡尔面矢量；一般仿射映射达到舍入误差。
- 光滑扭曲网格的度量恒等式与误差随加密按声明规律下降。
- 两套 profile 的公式、最小网格尺寸、物理边界闭合和交叉组合拒绝路径均有测试。
- 单块与多块切分的共享面坐标、面积和方向一致；旋转周期正确变换面矢量。
- 需要跨两个/三个连接的中间操作数具有唯一 donor 路径；缺失、分支或不一致路径初始化失败。
- 实际组装的 $D^Tw$ 或 $\mathcal D^TW_c=B^TW_b$ 满足残差、唯一性和正性要求。
- 将物理 ghost 几何填为 NaN 后全部几何测试通过。阶段 I 不接入 WCNS 流场推进。

## 7. 阶段 J：无粘 WCNS 与显式源项

### 7.1 目标与小任务

1. J1：实现两 profile 各自绑定的 $I_4^{PH}/D_4^{PH}/D_2^{PH}$ 和 $I_6/D_6$/单边 $D_4$。
2. J2：实现 `ReconstructionScaling`、线性重构和首个非线性 WCNS 重构，包含逐级正性回退与计数。
3. J3：实现 Rusanov `RiemannSolver`，只接受单位法向并由调用方乘面积；不建立通量分裂接口。
4. J4：实现公共 primitive ghost、同步 $p/U$、`InviscidBoundaryFaceState` 和 `strong_boundary_face_state`。
5. J5：实现唯一共享面及 PH 层 0--1、SCMM6 层 0--2 的无粘 `FaceFluxHalo`。
6. J6：实现 `uniform_conservative`、`body_force`、`manufactured`，每个 RK 子步按 $U^{(s)},\boldsymbol x_c,t^{(s)}$ 累加到 `Residual=dU/dt`。

### 7.2 阶段 J 卡口

- 线性插值、差分、重构和边界闭合通过精确矩或解析多项式测试。
- 恒定流在单块、多块和 MPI 下保持至规定舍入误差；一维/二维光滑问题达到声明收敛阶。
- 固壁默认强修正满足零法向质量通量，且无非物理无粘切向动量通量；关闭强修正的研究模式有独立日志和结果。
- 连接共享面只计算一套通量，通量 halo 的每层、符号、轴变换、版本和 owner 均有测试。
- 关闭源项与无源基线逐位一致；常量源、体力能量功和制造解满足时间精度及 $\sum W_cJ_c\mathcal S_c$ 全局平衡。
- 单块、串行多块和多 rank 的无粘残差及一个时间步状态在规定容差内一致。

## 8. 阶段 K：粘性 WCNS

### 8.1 目标与小任务

1. K1：实现公共 primitive ghost 参与的原始面值和守恒型真实单元梯度；不创建 ghost 几何或 ghost 梯度。
2. K2：实现 PH 两层、SCMM6 三层连接 `Gradient` halo 及粘性 `FaceFluxHalo`。
3. K3：实现常黏度和 Sutherland `TransportModel`、固定 $Pr$、Stokes 应力和 Fourier 热流。
4. K4：实现 `ViscousBoundaryTrace`，在原始结果后强制无滑移、绝热或等温真实壁面条件。
5. K5：实现粘性残差、$1/Re$ 单次缩放和 profile/维数/时间推进相关的粘性时间步限制。

### 8.2 阶段 K 卡口

- 线性速度场、线性温度场和仿射网格上的梯度、应力、热流达到解析值。
- Couette 流、热传导及至少一个粘性制造解达到预期收敛阶。
- 绝热壁法向热流为零；等温壁温和无滑移壁速度在真实面满足强约束。
- 改变 $Re$ 验证粘性残差严格按 $1/Re$ 缩放一次；Sutherland 在 $T=1$ 恢复参考黏度比例。
- 公共 primitive ghost 同时影响无粘原始重构和粘性原始导数，但无粘/粘性最终面修正互不覆盖。
- NaN ghost 坐标、度量和梯度测试通过；串行多块与 MPI 粘性结果一致。

## 9. 阶段 L：算法扩展与健壮性

阶段 L 的公式、配置、扩展接口和回退语义以
[`stage-l-design.md`](stage-l-design.md) 为冻结规格。MDCD 历史参考代码已经在公式核对完成后
移除；生产实现必须自行校验模板长度、参数和有限性，未知算法名不得静默返回。

### 9.1 目标与小任务

1. L0：人工冻结本阶段设计文档；在此之前不修改生产 C++。阶段 K 人工检查暂缓是显式的
   流程例外，不表示 K 已通过，也不允许把 K 或 L 合并到 `main`。
2. L1：建立 `IReconstructionScheme/ReconstructionRegistry` 和
   `IRiemannSolver/RiemannSolverRegistry`。拒绝未知名称、重复注册、错误模板和不兼容参数，
   并写入配置摘要、日志和重启签名；保留无需修改中央调用链的自定义扩展点。
3. L2：实现规范名称 `weno_js`、`weno_z`、`mdcd_linear`、`mdcd_hybrid`；`linear5` 只作为
   光滑基线和回退。MDCD 逐项遵循冻结公式，并补齐 `ReconstructionScaling`、有限性/模板
   检查和确定性失败语义。阶段 L 后又增加 `zero_order`，它仍接收六点模板，但左右值分别
   直接取第三、第四点，仅用于诊断、基线或强耗散试算。
4. L3：实现 conservative、primitive 和 characteristic 三种变量空间。特征重构对整个六点
   模板使用同一个面 Roe 平均法向特征基，固定切向基、特征归一化、尺度和回退次序。
5. L4：实现经典 Rusanov、HLLC 和带默认熵修正的 Roe；固定 HLLC 波速/星区公式和
   `Roe -> HLLC -> Rusanov`、`HLLC -> Rusanov` 回退链。
6. L5：实现重构正性保护、非有限值检查、Riemann 异常检查，以及按算法、原因、方向、
   面、块、rank 和 RK 子步汇总的降阶/回退诊断。共享连接面仍由唯一所有者计算和发布。
7. L6（可选、另行批准，当前未实施）：建立默认关闭的 `IPreconditioningModel`。开启模式
   必须同时覆盖稳态伪时间导数、Roe 特征系统、谱半径/CFL 和远场边界；物理时间 SSPRK3
   及其他求解器组合明确拒绝。当前 schema 不接受任何低 Mach 预处理键。
8. L7：建立常数/多项式、左右镜像、光滑收敛、接触、激波、低压、高 Mach、回退和
   单块/多块/MPI 一致性基准；阶段 H--K 全量回归继续通过。

### 9.2 阶段 L 卡口

- 四种必做重构的规范名称均可由注册表创建；常数保持、声明的光滑阶数、左右镜像和尺度
  不变性通过。MDCD-LINEAR 系数和 MDCD-HYBRID 传感器、四候选权、修正后首项为
  271779 的六点指标逐项与冻结参考一致；额外验证 $\beta_3$ 对常数为零且二次型半正定。
  错误模板、非有限值和未知名称确定性失败。
- 三种必做 Riemann 求解器满足一致性和法向反向测试；HLLC 的静止接触保持优于 Rusanov，
  Roe 通过线性波/激波及熵修正测试。异常状态严格按规定链回退且各级计数准确。
- 特征矩阵满足 $L_nR_n=I$；特征重构在均匀流、光滑波和激波问题上通过正确性、声明阶数
  及确定性切向基测试，失败时严格按文档退到 primitive/linear5/一阶。
- 每次降阶或回退均可在日志中定位；禁止无记录的算法切换。自定义测试插件证明新增策略
  无需修改通用重构、Riemann 或残差调用链。
- 当前没有低 Mach 配置键，经典三种求解器保持未预处理基线。若可选 L6 获准实施，还必须
  验证关闭模式与原基线逐位一致、合法组合有效、非法求解器/时间模式组合启动即失败，并
  单独给出低 Mach 收敛与稳态效率证据；未获批准时不得提供一个可开启但数学不完整的占位模式。
- 两个 profile 仍只能成套使用；算法扩展不得改变 $J,\boldsymbol S$、边界 ghost 或 `FaceFluxHalo` 语义。
- 单块、串行多块和多 rank 对共享面左右状态、唯一通量、回退计数及一个 RK 子步状态满足
  预定容差；全部阶段 H--K 回归继续通过。

## 10. 阶段 M：算例运行闭环、多块/MPI 系统验收与发布准备

原阶段 M 过度集中配置、分区、初始化、运行控制、输出和系统算例，现拆为 M--O。详细的
类型职责、配置字段、自动卡口和量化验收以 [`release-development-plan.md`](release-development-plan.md)
为权威规格。

### 10.1 目标与小任务

1. M0：冻结生产配置格式、错误策略和阶段设计。
2. M1：实现严格 `CaseConfig` 的读取、广播、版本和摘要一致性。
3. M2：实现 `StructuredPartitionPlan`。当 CGNS zone 少于 rank 或负载超过阈值时，采用
   PHengLEI 类似的受约束结构块二分；切分物理边界和原连接，建立兄弟连接，按 owner 读取
   坐标子区间，再将叶块确定性分配给 rank。
4. M3：实现均匀、区域分片、解析/制造和 CGNS 初场的 `FlowInitializer`。
5. M4：建立正式可执行程序的配置、网格、分区、度量、初场和短步生产启动链。
6. M5：以单 zone 的 1/2/4/8 rank、原生多 zone、轴变换和周期连接验证覆盖、负载、计划
   摘要、halo 和初始状态。

### 10.2 阶段 M 自动卡口

- 原 zone 单元和物理边界由叶块恰好覆盖一次；全部新旧连接均唯一、互逆且映射一致。
- 可行时 zone 数少于 rank 数仍使每个 rank 获得合法叶块；不可行时在分配场数组前报告
  模板约束和最大可用 rank，不能静默空闲。
- owner rank 只读取所属叶块坐标子区间；各 rank 的配置和分区摘要相同。
- 正式程序可从配置和 CGNS 网格完成初始化及受控短步运行；串行/MPI 初始状态一致。
- 公共 G0--G7 通过后创建阶段 M 里程碑并直接进入 N，不执行 G8。

## 11. 阶段 N：运行控制、停止、输出和重启

### 11.1 目标与小任务

1. N1：实现唯一 `SimulationDriver` 和 `steady | unsteady` 状态机。
2. N2：实现 MPI 全局残差、`StopController`、准确终止时间、最大步数/墙钟安全上限、数值
   失败和统一 `StopReason`。
3. N3：实现按步数、物理时间、显式时刻、初场和最终场触发且自动去重的输出调度。
4. N4：实现残差历史、全场物理/派生量和全局/区域/探针统计量，并提供自定义量注册接口。
5. N5：实现 CGNS/Tecplot 流场与 TXT/Tecplot 时间序列输出、原 zone 重组和独立重读。
6. N6：实现完整步检查点、严格签名以及相同/不同 rank 数和重新分区后的重启。
7. N7--N8：完成停止/I/O/重启自动测试和用户文档。

### 11.2 阶段 N 自动卡口

- 定常计算仅在所有启用残差分量连续满足冻结判据后正常收敛；非定常计算准确到达 `t_end`，
  不以残差提前停止；两者都由 `max_steps` 提供硬上限。
- 所有 rank 得到相同停止原因；非有限状态、安全信号和 wall-time 只在完整步边界退出或写检查点。
- 步/时间事件重合时只输出一次，干净停止总有最终场；关闭可选输出不改变求解状态。
- CGNS/Tecplot 流场和 TXT/Tecplot 历史可独立重读；字段、位置、单位、时间和内存值一致。
- 连续运行与检查点重启结果达到冻结容差，重启可改变 rank 数和合法叶块划分。
- 公共 G0--G7 通过后创建阶段 N 里程碑并直接进入 O，不执行 G8。
